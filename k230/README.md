# 亚博触摸屏 K230：触控菜单、相机与串口

当前程序提供**YOLO11 钢球识别、实时画面预览、LVGL 触控和串口联调**，接入指定上游仓库的 Model2。屏幕左侧显示 448×336 实时画面，识别到钢球时画绿色框和黄色中心；顶部显示状态，右侧显示主控信息与按键说明，底部保留四个按钮。像素到毫米的标定参数仍为 `None`，串口只发送 `LOST`，待实测标定后再启用有效毫米观测。模型来源、所需运行库和下载方法见 [MODEL.md](MODEL.md)。

## 文件与部署

- `main.py`：相机、协议、触控事件发送、菜单接收和速度估计。
- `touch_ui.py`：LVGL 界面和 `TOUCH(0)` 输入。与 `main.py` 一起部署。
- `steel_ball_detector.py`：调用板上原生 YOLO11，解码 steel 检测结果。
- `kmodel/steel_ball_model2_nncase2.9.kmodel`：钢球模型，先在电脑运行 `py tools/download_steel_ball_model.py` 下载，再上传到 `/sdcard/kmodel/`。
- `balance_ui_20.fnt`：预览界面使用的 20 像素中英文字库，必须上传到 `/sdcard/balance_ui_20.fnt`。旧的 28 像素字库可保留供旧版恢复。
- `FONT_LICENSE.txt`：字库所用思源黑体的 SIL Open Font License 授权文本。
- `model_manifest.json`、`MODEL.md`：模型来源与校验信息；PC 测试在 `tools/test_*.py`，不用上传到板上。

1. 使用亚博适配的 CanMV K230 固件和 CanMV IDE；这不是 STM32 的 `.hex` 固件。
2. 先将 K230 内存卡 `/sdcard/main.py` **复制到电脑备份**。保存新 `main.py` 会替换原来的开机程序，可能是亚博自带 GUI。不要删除卡上的其他目录、库或模型。
3. 在 CanMV IDE 连接设备，停止原程序，先把 `touch_ui.py`、`steel_ball_detector.py`、`balance_ui_20.fnt` 和 `FONT_LICENSE.txt` 上传到 `/sdcard/`，将模型上传到 `/sdcard/kmodel/`，保留原生 `libs` 目录，再打开本目录的 `main.py` 点击运行。
4. 正常时，左侧持续显示摄像头画面，无球或暂停识别时也会刷新。有球时叠加绿色框与黄色中心，顶部显示像素坐标、置信度或 `YOLO: NO BALL`；未标定时显示 `CALIBRATION PENDING`。没有配套主控连接时显示“未收到主控回包”，有连接后右侧显示主控返回的四行文字。
5. 确认相机和屏幕正常后，使用 IDE 的“保存当前脚本到 CanMV 板（作为 main.py）”，重启验证离线运行。
6. 恢复原 GUI 时，把备份的 `/sdcard/main.py` 放回原处并重启。

官方说明：[相机示例](https://www.yahboom.net/study/K230/15017/)、[离线运行](https://www.yahboom.net/study/K230/14973/)。

## 触控替代实体按键

触控界面参考了设备上的以下原生文件；这些原生文件保持原样：

- `/sdcard/ybMain/main.py`：640×480、LVGL BGRA8888 缓冲、显示刷新和 `TOUCH(0)` 回调。
- `/sdcard/02.lvgl_button.py`：`lv.btn`、`lv.EVENT.CLICKED` 的按钮事件。
- `/sdcard/ybUtils/YbUart.py`：IO9/IO10 的 UART1 映射。

本程序独立运行，采用相同的 LVGL/触摸 API，暂未注册成原生桌面的应用，也不需要修改 `ybMain`、`ybUtils`。预览版字库由设备原有的 `/sdcard/res/font/SourceHanSansSC-Normal-Min.ttf` 生成，使用 20 像素、4 位抗锯齿，包含 ASCII 和当前界面所用中文。修改中文提示时，需要同步补充字库字符。

显示驱动显式设为 `lv.COLOR_FORMAT.ARGB8888`，与两个 `image.BGRA8888` 图像缓冲匹配，保留对应 bytearray 引用；刷新时按 LVGL 提供的地址选择实际缓冲。LCD 仍只使用 `LAYER_OSD0` 一个图层：448×336 RGB565 预览作为 LVGL 图像，与文字和按钮一起合成。预览像素复制到持久缓冲，避免相机复用帧缓冲时撕裂；不把相机和 UI 分别写到两个显示图层。AI 使用通道 2 的 640×480 RGBP888，预览使用通道 0 的 RGB565。显示验证应使用 VO/WBC 合成输出，而不只检查 LVGL 内存缓冲。

### 摄像头安装水平辅助线

预览中有一条红色水平线，不需要检测到钢球就会显示；暂停识别时也保留。安装摄像头时，让管道中心沿这条线放置，并调整摄像头角度，使管道与横线平行。

位置在 `touch_ui.py` 文件顶部的 `ALIGN_LINE_Y` 调整：

```python
ALIGN_LINE_Y = PREVIEW_HEIGHT // 2  # 默认 168
```

坐标以左侧 448×336 预览为准，原点在预览左上角，范围为整数 `0..335`；数值变小向上、变大向下，例如改为 `ALIGN_LINE_Y = 150`。默认端点为 `(0,168)` 到 `(447,168)`；对应整屏坐标 `(8,232)` 到 `(455,232)`，对应 640×480 AI 图像的 Y=240。绘线的红色与 2 像素粗细在 `TouchMenu.update()` 的 `frame.draw_line(...)` 修改。将修改后的 `touch_ui.py` 上传到 `/sdcard/` 并重启生效。辅助线不参与模型推理，不会自动设置毫米零点或比例。

### 当前 F407 通讯测试固件的按键

| 屏幕按钮 | 当前实际作用 |
| --- | --- |
| 上移 +1 | F407 的通讯测试值 V 加一，不是让小球或平台上移 |
| 下移 -1 | 测试值 V 减一 |
| 确认/启停 | F407 回传 START/STOP，切换 K230 钢球识别；预览始终继续 |
| 返回/清零 | 测试值 V 清零，不是回零电机 |

四个按钮发送的事件编号不变。以下正式菜单说明适用于根目录 MSPM0 平衡固件，不能将其理解为当前 F407 通讯测试已经具备这些电机控制功能。

### 屏幕文字和数字

| 屏幕信息 | 含义 |
| --- | --- |
| 主控菜单已同步 | K230 收到了 STM32 的菜单回包，只证明 STM32→K230 方向有有效数据 |
| YOLO: NO BALL | 当前没有达到筛选条件的钢球检测结果，不代表模型没有加载 |
| YOLO X/Y/C | 钢球中心 X/Y 为原始 640×480 图像的像素坐标，C 为置信度百分比；左侧预览已缩小为 448×336 |
| CALIBRATION PENDING | 尚未填写像素到毫米的标定，观测仍发送 LOST |
| F407 RX:OK/WAIT/LOST | STM32 最近 1.5 秒收到有效 K230 帧 / 从未收到 / 接收超时 |
| N | STM32 累计收到的有效观测、按键和菜单同步请求总数，显示值取模 100000 |
| OBS | STM32 累计收到的小球观测帧数，包含 LOST 帧，显示值取模 100000 |
| OBS 后的 LOST/VALID | 最近一帧观测的状态；未标定或没检测到球时 LOST 正常 |
| KEY | STM32 最近收到的真实按键事件；菜单同步请求不会覆盖它 |
| V | 按键通讯测试值，上移加一、下移减一、返回清零，不是速度或小球坐标 |
| RUN:ON/OFF | STM32 请求的视觉识别启停状态，OFF 时预览和通讯仍继续 |
| E | STM32 的 UART 硬件错误与接收缓冲溢出累计计数，显示值取模 1000 |
| C | STM32 的 CRC 校验失败累计计数，显示值取模 1000；与顶部 YOLO 置信度 C 不同 |

正常双向通讯应同时看到顶部同步、`RX:OK`，且 N/OBS 持续增加。E/C 的非零值表示发生过错误，判断当前是否异常要看计数是否持续增长。调试暂停或刚启动时 RX 可能短暂为 LOST；若持续如此，应排查 K230→STM32 方向。

| 屏幕按钮 | 操作 |
| --- | --- |
| 上 / Up | 上移菜单光标，或选择加号 |
| 下 / Down | 下移菜单光标，或选择减号 |
| 确认 / 停止 | 进入选项、修改一次参数；平衡运行中停止并归零 |
| 返回 / Back | 返回上一级；平衡运行中同样停止并归零 |

保留原有五项功能：`Set Target`、`Ball Balance`、`Auto Seq`、`Tuning`、`Show Data`。使用“上/下”选中，再点击“确认”。调参中的 KFF/KFF2 速度补偿仍保留。四行文字由主控反馈，不在 K230 上猜测或重复实现主控菜单状态。实体按键的 GPIO 配置和读取入口已移除，OLED 仍同步显示。

K230 每秒请求一次菜单快照；连续 3 秒没有快照会显示“未收到主控回包”。这个提示只说明未收到配套协议的菜单反馈，不能据此判断线缆是否连接。主控固件尚未适配、波特率或接线不匹配时都会出现该提示；它也不代表钢球检测有效或电机已到位。一次正常点击发一个导航事件，长按不连发。切换运行模式要先停止返回主菜单，再选择另一模式。

**必须同步更新主控程序**。仅替换 K230 文件，旧主控无法识别触控事件或返回菜单。根目录主控仍是 MSPM0 平衡工程；新增的 [STM32F407 通讯测试工程](../stm32f407_uart_test/README.md) 提供完整 Keil 源码和 HEX，可先验证双向通信与触控反馈。测试固件的按钮用于调整测试值和切换观测，不实现上述正式平衡菜单，也没有移植平衡控制。

## 接线

默认串口为亚博通信接口的 UART1，`115200 / 8N1`，IO9=TX，IO10=RX。

| K230 | STM32F407VET6 |
| --- | --- |
| TX / IO9 | PD9 / USART3 RX / AF7 |
| RX / IO10 | PD8 / USART3 TX / AF7 |
| GND | GND |

接线已确定为 USART3 的 PD8/PD9，配套测试固件使用相同配置。K230 可先通过 Type-C 供电，两板共地，信号为 3.3 V TTL；不要把接口的 5V 电源脚接到串口信号脚。

官方依据：[亚博接口与 IO 映射](https://www.yahboom.net/study/K230/14977/)、[CanMV UART API](https://www.kendryte.com/k230_canmv/en/v1.3/api/machine/K230_CanMV_UART_API_Manual.html)。

## 串口协议

沿用本工程 `user_driver/mspm0_k230_comm.h/.c` 定义的协议，**不是亚博出厂 GUI 的通用协议**。K230 与 STM32 必须运行配套的发送和解析程序。

| 偏移 | 内容 |
| --- | --- |
| 0–1 | 帧头 `A5 5A` |
| 2 | 版本 `01` |
| 3 | 负载长度 `0C` |
| 4–5 | 序号，uint16 |
| 6–9 | 本程序启动后的时间戳 ms，uint32 |
| 10–11 | X 位置 mm，int16，以平台目标零点为参考 |
| 12–13 | X 速度 mm/s，int16 |
| 14 | 置信度 0–100；未来检测器须归一到这个范围 |
| 15 | `01`=检测有效，`20`=无效/丢球 |
| 16–17 | CRC16，覆盖偏移 2–15 |

所有多字节字段小端序；CRC16-CCITT-FALSE，多项式 `0x1021`、初值 `0xFFFF`、不反射、无最终异或。

主控指令为 7 字节：`A5 5A 01 01 CMD CRC低 CRC高`，CRC 覆盖 `01 01 CMD`。`CMD=30` 开启视觉观测，`CMD=31` 停止视觉观测；这些是主控发给 K230 的指令。停止后继续发送 `LOST`，不会保留旧坐标作为有效数据。上电默认发送，进入 `Show Data` 时主控也会重新开启视觉观测。

K230 发给主控的触控事件采用同样的 7 字节封装：`40`=上、`41`=下、`42`=确认、`43`=返回、`44`=请求菜单快照。主控在 UART ISR 里校验、入队，由主循环处理，不在中断里运行 PID、OLED 刷新或阻塞发送。

主控菜单快照为 95 字节：`A5 5A 01 59 50 [4×22字节菜单行] CRC低 CRC高`。菜单行为 ASCII、零填充，每行最多 21 个可见字符；CRC 覆盖版本、长度、类型及全部菜单行。K230 支持拆包、混合指令和快照、CRC 错误拒绝。

目标循环周期 20 ms，**实际帧率由相机、处理与显示耗时决定**，不能保证 50 fps。速度按实际采样间隔计算，并进行一阶低通。现有主控收到 `LOST` 后会忽略该帧，连续约 500 ms 没有有效观测才停止电机，并非立即停机；这是原控制代码的行为，本次没有修改。

## 识别检查与毫米标定

模型已接入，正式用于控制前还需完成以下两步：

1. `SteelBallDetector.detect(frame)` 已接入 Model2：输入为 640×480 RGBP888，返回 `(球心x像素, 球心y像素, 置信度0到100)`，没有球返回 `None`。先验证本平台的识别效果，并将 `steel_ball_detector.py` 的 ROI 限制在实际平台内。
2. 填写 `X_ZERO_PX` 和 `MM_PER_PIXEL`，使 `x_mm = (x_px - X_ZERO_PX) * MM_PER_PIXEL`。例如实测两点在图像上的距离为 Δpx、平台上的实际距离为 Δmm，则比例的绝对值为 Δmm/Δpx，符号按主控的正方向确定。示例公式不是默认标定值。

首次检测/丢球后重新检测时，速度从 0 开始估计；低置信度、越界、非有限数、过期的连续采样或超出协议数值范围都会发送 `LOST`。

当前与原工程一样只输出 X 单轴。相机倾斜、透视变化或平台倾斜导致的投影变化明显时，需要更完整的几何标定；二维平台也需要扩展 Y 轴协议和控制，不能只改相机端。

## PC 检查

### 接上主控后黑屏的兼容性修复

本板 MicroPython 不支持 `del bytearray[...]`。旧解析器在首次收到帧头时会执行切片删除并抛出 `TypeError`，随后退出程序、关闭显示。已将接收缓冲中的删除操作改为兼容的切片赋值，保持串口协议不变；无需为此重新烧录 F407。新增接收测试模拟该固件限制，并覆盖菜单分包、连续回包、错误头、CRC 错误和同步恢复。

修复后用户已确认：两板供电、串口保持连接并重新上电，K230 正常启动，显示“主控菜单已同步”。实际串口收包应单独验证；空场推理、没有收到主控数据的运行测试不能覆盖接收路径。

在工程根目录运行：

```powershell
py -B -m unittest discover -s tools -p "test_*.py" -v
```

如果使用的不是 Windows Python 启动器，可将 `py` 换成 `python3` 或实际的 Python 命令。

当前 Python 测试覆盖本板 YOLO11 检测结果格式、ROI/置信度筛选、无效检测和未标定时发送 LOST，以及 LVGL 缓冲与触控事件绑定。F407 的 C/串口协议互通测试见 `stm32f407_uart_test/Tests/`。

预览相关检查还覆盖 RGB565 图像缓冲、检测框缩放与无球时继续刷新。启动异常会保存到板上 `/sdcard/balance_error.log`，用于固件 API 或资源初始化问题的定位。

板上模型加载、相机推理与显示应分别验证；没有实际钢球的相机空场推理不能证明本平台的检测精度，也不能替代毫米标定与双板闭环测试。
